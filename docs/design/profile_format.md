# ダイアグラムプロファイルの書式

netoviz2 の **schematic レイアウト** (`?layout=schematic`) で、トポロジを「構成図」として配置するための定義 (プロファイル) の書式です。
トポロジ (node / term-point / link) には描画用の情報を持たせず、見やすさのための情報 (どの機器がどの拠点・階層・冗長ペアか)
を、CSS のように、トポロジとは別のファイルで持ちます。設計は [schematic_layout.md](schematic_layout.md)、レイアウトの全体は [layout.md](layout.md)、構成は [../architecture.md](../architecture.md) を参照してください。

## 置き場所と使い方

- 正本: playground の `profiles/<network>/<名前>.yaml` (git 管理。人が書く YAML。`topologies/` は自動生成なので使わない)。1 つのファイルに複数のプロファイル (`---` 区切り) を書ける。
- 配信: netomox-exp が `profiles/` を読み、YAML を **JSON に変換**して `GET /topologies/:network/netoviz2/profiles` で返す ([API 仕様](https://github.com/ool-mddo/playground/blob/main/docs/netoviz2_data_format.md))。netoviz2 は YAML を読まない。JSON で表せない書き方 (アンカー・エイリアス・タグ) は使わない。
- **選択 (自動):** schematic レイアウトのとき、netoviz2 は、表示中の network のプロファイルから、レイヤごとに次の条件に合う**最初のもの** (ファイル名の昇順 → ファイル内の順) を使う。
  - `target.network` が表示中の network に合う (省略すると全 network)。
  - `target.snapshot` (正規表現。全体一致) が表示中の snapshot に合う (省略すると全 snapshot)。
  - `target.layer` が、そのレイヤに一致する (省略すると全レイヤ)。
  - 表示中の snapshot が分からないときは、`target.snapshot` は検査しない。
  - 不正な文書 (キーや型の誤り、不正な正規表現) は、その文書だけを警告付きで使わない (同じファイルの他の文書は使う)。`?profile=` でファイルを指定したときは、不正な文書があればファイル全体をエラーにする。
  - 使われているプロファイル (ファイル名、文書の番号、自動か指定か) は、schematic のパネルに表示される。
- **選択 (指定):** `?profile=<名前>` で、そのファイルだけを対象にする (同じ条件で選ぶ)。
- **プロファイルが無くても動く:** 合うものが無いレイヤは、下位レイヤからの継承 (support をたどる)、名前とリンクからの推論、の順に試す。
  推論した結果は「下書き」として、画面 (schematic のパネル) から YAML でダウンロード / コピーできる。下書きを直して、`profiles/` に置くのが基本の流れ。

## 書式

1 つのファイルに複数のビュー (`---` 区切りの YAML 文書) を書ける。ビューごとの項目:

| キー             | 内容                                                                                                                                                                                |
| ---------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `view`           | ビューの名前 (必須)                                                                                                                                                                 |
| `target`         | `{ network, snapshot, layer }`。適用先を絞る。`network` と `layer` は文字列の一致、`snapshot` は正規表現 (全体一致。例: `'original_asis\|emulated_asis'`)。省略した項目は全部に合う |
| `tiers`          | 階層の名前を、上流 (上) から下流 (下) の順に並べたリスト                                                                                                                            |
| `keepEmptyTiers` | `true`: ノードが 1 つも無い階層も、空の行として残す (既定は、ノードの無い階層の行は作らない)。詳細は「空の行 (`keepEmptyTiers`)」                                                   |
| `symmetry`       | `{ axis, mirror }`。`axis` の列を中心に、`mirror` の列の組を左右に等距離に置く。詳細は「列の鏡像配置 (`symmetry`)」                                                                 |
| `name`           | ノードの名前 (ID ではなく `name`) を分解する正規表現 (名前付きグループ。例: `site` `role` `index`)                                                                                  |
| `inherit`        | `{ from: <レイヤ ID>, via: supports }`。そのレイヤの配置 (拠点・階層・並び) を support をたどって引き継ぐ (省略すると自動で候補を試す)                                              |
| `rules`          | 規則のリスト。**後に書いた規則が勝つ** (項目ごと)                                                                                                                                   |

規則 (`rules`) の項目:

| キー     | 内容                                                                                                                                                                                                          |
| -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `select` | セレクタ。`*` (すべて)、`#id` (ID または名前)、`[キー=値]` (名前の分解で得た値、`kind`、`name`)、およびそれらの連結 (例: `[site=a][role=br]`)                                                                 |
| `tier`   | 階層の名前 (`tiers` のどれか)。同じ階層のノードは同じ高さに並ぶ                                                                                                                                               |
| `group`  | 拠点 (列) の決め方。名前付きグループの名前 (例: `site`) か、固定の値 `{ value: <値> }` (例: `{ value: core }`)。同じ値のノードが 1 つの列にまとまる。詳細は「拠点 (group) の決め方」                          |
| `order`  | 拠点の左右の順序 (小さいほど左)。**拠点 (group) の順序**で、グループの中の最小値が使われる                                                                                                                    |
| `align`  | `center`: 拠点 (列) の各行を、その列の軸に揃えて、左右対称にする。詳細は「左右対称 (`align`)」                                                                                                                |
| `pair`   | 冗長ペア: `{ by: <グループ名>, primary: '<値>' }`。`by` 以外が同じノード (例: 同じ拠点・同じ役割で番号違い) をペアにし、`primary` の値のほうを左に置く。`primary` は引用符で囲む (`01` が数値の 1 になるため) |

未知のキーは無視され、画面に警告が出る。まだ対応していない設計案のキー (`axes`、`shape`) も同様。

## 拠点 (group) の決め方

拠点 (group) は、図の「列」にあたる。同じ値の group を持つノードが 1 つの列 (全行を通じて 1 つのブロック) にまとまり、列どうしは重ならない。規則の `group` には 2 通りの書き方がある。

| 書き方                   | group の値                                                                                                |
| ------------------------ | --------------------------------------------------------------------------------------------------------- |
| `group: site`            | `name` の正規表現で得た名前付きグループ `site` の値。そのグループが無い (マッチしない) と、group が外れる |
| `group: { value: core }` | 固定の文字列 `core` (v0.4.0 以降)。名前の分解に依らず、選んだノードすべてが同じ group になる              |

- `value` は空でない文字列。`'01'` のような数字に見えるものは引用符で囲む。空・文字列でない・`value` が無いときは不正な文書になる。
- 規則は**後に書いたものが勝つ**ので、`group: site` で全体に与えてから、一部のノードだけ `group: { value: ... }` で上書きできる (逆も同じ)。
- 固定の値は、名前の付け方が違うノードを同じ列に置きたいときに使う (下の例)。

### 列の左右の順序 (`order`)

- `order` は列 (group) の左右の順位で、group のノードのうち**最小の `order`** が使われる (小さいほど左)。順位の無い group は、それらの後ろに名前順で並ぶ。同じ値のときは名前順。
- **`order` は別の group を同じ列にはしない。** 同じ列にするには、同じ group の値にする (上の `group: { value: ... }`)。
- group を持たないノード (`group: site` で `site` が取れなかったものなど) は、まとめて**最後の 1 列**になる。この列は `order` で動かせない。

### 左右対称 (`align: center`)

既定では、行の中のノードは、リンク先の位置に近づくように置かれる (リンクが縦になる)。このため、木のような構成でも、たとえば 4 つの endpoint が、つながる core の片側に寄ることがある。
`align: center` を拠点 (列) のノードに書くと、その列は左右対称に置かれる。

- その列の各行 (同じ tier の、その列のノード) を、列の軸に揃える。軸は、列の左端と右端の中心。行の中の順序と最小間隔は守る。
- 列の性質で、列のどれか 1 つのノードに書けば、列全体に効く (例: `{ select: "*", align: center }` で全列、`{ select: "[site=a]", align: center }` で 1 つの列)。
- リンクを縦にする力より優先するので、リンクが斜めになることがある。
- 列の幅は、いちばん広い行に合うので、軸を揃えた結果として列の幅が広がる場合は、列どうしの間隔を取り直す (列の全体を動かすので、対称性は保たれる)。
- `value` を使った中央列 (`group: { value }`) にも使える。

### 空の行 (`keepEmptyTiers`)

既定では、ノードが 1 つも無い階層は行にならず、詰められる。上流側と下流側で階層の数が違う図 (例: 上流の AS には `core01` の階層があり、下流の AS には無い) では、自分を中心にした上下の行数が揃わない。
プロファイルの最上位に `keepEmptyTiers: true` を書くと、`tiers` に書いた階層をすべて行として残す。

- 空の行の高さは、図でいちばん大きいノードの高さ。行どうしの間隔は、ほかの行と同じ。
- 階層に入らないノード (分類できないもの) の行は、使われたときだけ最後に付く。
- 空の行を、リンクが通ることがある (経路は、ノードとポートを避ける)。

### 列の鏡像配置 (`symmetry`)

`align` が列の**中**の対称なのに対し、`symmetry` は**列どうし**の左右対称を保証する。たとえば Y 字の左右の外部 AS が、中央の列から等距離に置かれる。トポロジが偶然対称なときだけでなく、列の幅が違うときも成り立つ。

```yaml
symmetry:
  axis: center # 中心にする列 (group の値)
  mirror: [[as65550, as65560]] # 左右に等距離に置く列の組 (複数書ける)
```

- 列は、`group` の値 (名前から取った値か、`group: { value }` の固定値) で指す。
- 列の位置は、列の左端と右端の中心。組の 2 つの列は、軸の列の中心から等距離になる。左右は、現在の位置 (`order`) で決まる: 左にあるほうが左になる。
- 2 つの列のうち、軸から遠いほうに距離を合わせ、近いほうを外へ動かす。列どうしの間隔は、狭くならない。
- 組のうち、存在しない列 (ノードが無い) があるときは、その組を無視する。軸の列が無いときは、すべて無視する。
- 列の位置だけを合わせる。2 つの列の**中のノード**が鏡像になることまでは、保証しない (中を対称にするには `align` を使う)。
- 外へ動かした列が、さらに外側の列と重なるときは、列の間隔を取り直すので、鏡像が保たれないことがある (列の間に余裕を持たせるか、`order` を見直す)。

### 例: Y 字 (上に外部 AS を左右に、下に自 AS を縦に)

```yaml
tiers: [up, own_edge, own_core, down] # 上 = 上流
rules:
  - { select: '*', group: site } # 名前から取れる AS ごとに 1 列
  - { select: '[tk=tk]', group: { value: center } } # 自 AS (名前に site が無い)
  - { select: '[site=as65520]', group: { value: center } } # 下流 AS も同じ列
  - { select: '[site=as65550]', order: 1 } # 左
  - { select: '[tk=tk]', order: 2 } # 中央 (center 列の順位は、メンバーの最小の order)
  - { select: '[site=as65560]', order: 3 } # 右
```

列は左・中央・右の 3 本になり、行 (tier) が列をまたいで共有されるので、上の行は左右の列だけ、下の行は中央の列だけにノードが入り、Y 字に見える。実例は playground の `profiles/mddo-bgp/asis.yaml`。

## 例

playground の `profiles/mddo-fw/asis.yaml` (3 拠点の FW 構成。拠点が左右、br → fw → cr → seg → host が上下、1 と 2 が冗長ペア)。`profiles/mddo-bgp/asis.yaml` (自 AS を中央の縦列に、外部 AS を左右に、下流 AS を下に置く Y 字。`group: { value }`・`align`・`symmetry`・`keepEmptyTiers` をすべて使う)。
`profiles/mddo-fw/asis_y.yaml` (DC = site-a を中央の縦列に、拠点 = site-b / site-c を上の左右に置く Y 字。`align`・`symmetry` を使う。`asis.yaml` の別案で、`?profile=asis_y` で選ぶ)。

## 方針

- 描画用の情報は、トポロジに持たせず、ここに置く。コード (netoviz2) は、`kind`・ユースケース・ネットワーク名・命名規則で分岐しない。ドメインの知識はすべてこのファイルに書く。
- セグメントのような「機器どうしをつなぐ接続点」は、配置の主体ではないので、プロファイルに書く必要はない (機器の配置が決まった後に、つながる機器の間に置かれる)。
  - 下位レイヤから継承するときは、下位の 2 つ以上のノードに支えられるノードが接続点になる。
  - 下位レイヤの候補が無く、プロファイルで配置するとき (例: `emulated_asis` の layer3) は、**どの規則も階層を与えず、階層を持つ 2 つ以上のノードとつながるノード**が接続点になる。
  - 名前の誤記で階層を持たない機器も、2 つ以上の機器とつながっていれば、接続点として置かれる (例外として報告されない)。下位レイヤの候補があるとき (継承できるレイヤ) と、推論のときは、この判定をしない (階層を持たないノードは、例外として報告される)。階層を持たず、つながる機器が 1 つ以下のノードは、従来どおり例外として報告され、一番下の行に置かれる。
